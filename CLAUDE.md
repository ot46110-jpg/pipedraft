# PipeDraft 3D

Offline 3D piping layout tool for the owner's iPad (Safari, installed to the Home Screen). Single user, no App Store. Inspired by the data model of AutoCAD Plant 3D: spec-driven fittings, ports, branch table, BOM.

## Layout
- `src/index.src.html` is the source. Edit this file only.
- `vendor/three.min.js` is Three.js r128, inlined into the build.
- `build.js` writes `index.html` (one self-contained file) and `sw.js` (new cache name per build).
- `test/bom.test.js` runs the app headless and checks the example BOM.
- `manifest.json`, `icon-180.png`, `icon-512.png` are static.
- GitHub Pages serves the repo root from `main`. Pushing `index.html` and `sw.js` publishes the app.

## Commands
- `npm run build` then `npm test`. Run both before every commit, and commit the generated `index.html` and `sw.js` with the source.

## Rules
- The app must work with no network. No CDN scripts, web fonts or fetches in `src/index.src.html` other than the Three.js tag that `build.js` inlines.
- Never edit `index.html` or `sw.js` by hand.
- Units: scene is metres, UI shows millimetres. Pipe sizes are NPS 1/2, 3/4, 1, 1-1/2, 2, 2-1/2, 3, 4, 6, 8, 10, 12 (`NPS_LIST`, keyed by the number, `nl(n)` gives the label) with ASME B36.10 OD and schedules 40 and 80. Every size table is built with `byNps([...])` in `NPS_LIST` order. A new size needs an entry in `SIZES`, `COL` and every `byNps` table (tee, cap, reducer length, flange, bolts, valve face to face, items, supports span, FT, Cv).
- Exact input (all mm, CAD axes: X, Y horizontal, Z up; the scene is Y-up so CAD Y is scene Z, use `cadOf`/`sceneOf`): while drawing, the `lenIn` field in the context bar adds a pipe of that length along the locked axis (or the last aimed direction in Auto; a negative number reverses) and its placeholder shows the live length under the finger; `Start at…` starts a run at typed X, Y, Z. Selecting a pipe shows length and both end coordinates; changing one calls `stretchPipe`, which moves the piping beyond that end (`componentFrom`, never through the edited pipe) with its valves, flanges, supports, instruments, caps and joint overrides, and refuses when the far side is a closed loop, touches an equipment nozzle, passes under the floor or leaves a pipe under 50 mm. "Move, copy, mirror" in the same panel runs `applyGroup` on the connected piping (move, stepped copies with a count, mirror about the pipe start, rotate 90°); copies renumber instruments and re-link them to the copied valves. Placed items have a typed distance from their pipe start (`posHtml`). Piping tied to equipment cannot be moved as a group.
- Fabrication (⋯ → Sheets → Cut list and welds, `fabrication()`): pipes are cut into pieces between the fittings, valves, items and flanges on them (`pipeTrim` from `rebuild()` gives the fitting trims; flange pairs and blinds now take `flangeSpan` out of the pipe in the BOM too, so cut lengths always sum to the BOM pipe quantity). Welds are numbered W1… in the order found (BW, SW, fillet for slip-on); bolted and threaded joints are listed apart and carry no weld number. `model.field[key]` marks a weld as field (key = pipe index + position in mm, so moving a pipe loses its marks). Spools are the parts still joined by shop welds; bolted joints, threaded joints and field welds break them. An olet joint is welded to the header and the branch; a header split at an olet is merged into one cut piece. Pieces are named `S01-1`; collinear pipes drawn separately stay separate pieces with a weld between them. The iso sheet prints weld numbers, field welds as open circles. CSV export from the sheet or the File group.
- Iso sheet (`isoSvg(ln, view, tidy)` wraps `isoCore(rot)`): header controls pick the line number, the view and Auto layout, plus Title block (project, client, drawing no., revision, date, drawn, checked in `model.title`; service, class, design P and T, insulation per line in `model.lines[ln]`) and Print / PDF (print CSS shows only the sheet, the user saves as PDF from the print dialog). A sheet for one line swaps in `subsetFor(ln)` as the model and calls `rebuild()` so the material list, cut list and welds cover that line only, then restores the model; never keep state from `rebuild()` across that call. Auto view tries the four quarter turns of the model about the vertical axis and keeps the one with the fewest crossing pipes (`crossings()`), then the largest drawing. Auto layout (`want`/`layoutLabels`/`boxCost`): balloons, weld numbers, instrument tags and elevations are queued with candidate offsets and placed by priority where they hit no pipe segment (`segs`), symbol or earlier label (`occ`) and stay inside the drawing area; dimension lines pick the side and distance with the fewest conflicts. A symbol or label drawn directly into `body` should register its box in `occ`. The right column also carries a cut list; the bottom is a two-row title block (110 px, `TB`).
- Eccentric reducers: `spec.eccFlat` (bottom, top, side) with a per-joint override `fit[key].flat`; on vertical pipe it is always side. The cone stays on the centreline and a orange line marks the flat side, the BOM says "flat on top/bottom/side", the iso writes FOT, FOB or FOS, and a warning appears when the reducer next to a pump suction nozzle (nozzle 0 of a pump) is flat on bottom.
- Vent and drain (Parts → Ends): a 3/4 (1/2 on small pipe) branch 0.3 m up or down from a horizontal pipe with a ball valve and a plug, built from ordinary pipe, valve and cap records, so BOM, welds and iso need no special case. A drain needs 0.25 m below the pipe.
- Slope: `pipe.sl` (1 in N) and `pipe.sld` (1 falls toward the end, -1 toward the start), set in the pipe inspector. It is a note on the iso (arrow and "SLOPE 1:N"), the geometry and elevations are not changed.
- Backups: `save()` writes the project and `takeBackup(false)` keeps a rolling set of 8 snapshots in localStorage `pipedraft.backups.v1` (at most one per two minutes, never an empty project, never an unchanged one); a backup is forced before Clear everything and Open project, and before a restore. File → Backups lists them with Restore (undoable). A failed save toasts once. The app also asks the browser for persistent storage. Snapshots live in the same browser storage as the project, so File → Save project is still the only copy that survives cleared site data.
- Tags and handwheels: any valve, flange pair, inline item, support or equipment can carry `tag` typed in the inspector; `assignTags()` uses it in place of the automatic one but still counts the automatic number, so other tags do not shift, and a duplicate tag raises a warning. Valves have `hw`, the angle in degrees around the pipe of the stem, handwheel or actuator (0 is up, or toward X on vertical pipe); the valve group is rotated about the pipe axis in `rebuild()` (three-way valves keep `rot` for the side port). On the iso a valve whose handwheel points down is drawn upside down.
- PDF: the sheet header's Save PDF draws the open sheet's SVG to a 2400 px canvas (`svgToJpeg`), saves a JPEG and wraps it in a one-page A3 landscape PDF with `buildPdf`, no library and no network. It is a raster image, so text cannot be selected; Print stays for a vector PDF through the system dialog. Chrome desktop was checked end to end; iPad Safari goes through the share sheet (`saveBlob`).
- Line list (⋯ → Sheets → Line list, `lineList()`): one row per line number with size(s), pipe length, valves and welds counted from the drawing, and typed service, class, design P and T, insulation, which live in `model.lines[ln]` (same fields the iso title block reads). CSV from the sheet or the File group. Per-line data is descriptive text only; it does not change the BOM or fittings.
- Clash check (`clashes()`, reported through `warns` by `clashWarnings()` at the end of `rebuild()`): pipes are cylinders of their outside diameter; two pipes clash when their axes pass closer than the sum of the radii minus 4 mm, unless an end of one lies on the other (a joint or a branch). A pipe clashes with equipment when it runs inside the outline (pump box, vessel cylinder, shrunk 30 mm) farther than 0.3 m from that equipment's nozzles. A valve is a cylinder along its host pipe (face to face long, radius the larger of the pipe radius and 0.75 of the flange radius); another pipe clashes with it when its axis passes closer than the radii sum minus 4 mm (kind 'valve', i = host pipe, j = the other pipe), ignoring the stretch next to the end of a pipe that starts on the valve's host pipe, radii sum plus half the valve length (a branch tee beside a valve, or the next straight pipe, is normal); a pipe that clashes with the valve and its host is listed once, as the valve. At most 8 are listed, with CAD mm coordinates. Supports and insulation are not checked.
- Sheet zoom (every sheet in `#isoSheet`): `isoZ` (1 = fit, up to 8) sizes the svg as a multiple of the window (`applyIsoZoom`, `zoomIso`) and the window scrolls, so one finger pans. Header buttons − / Fit / + , two-finger pinch (pointer events; `#isoSheet` is `touch-action: pan-x pan-y`) and ctrl+wheel zoom about the pinch point. `showSheet` resets to Fit; editing the title block keeps the zoom. Print CSS forces the svg back to 100%. Page-level pinch stays blocked (`gesturestart`), so the 3D canvas is not affected.
- Single flanges and valve ends: a flange record is either a pair (two flanges on one point) or one flange (`isOne(f)`: blind `t:'bl'`, at a pipe end `e:1`, or against a valve `m:1`). A single flange has its face at `p`, `d` points toward the part it mates with, and its body runs back along the pipe (`flangeSpan` = thickness + 4 mm gap, taken out of the pipe length and the cut list). The flange tool near a free pipe end (within 0.35 m or a third of the pipe, `endBusy()` says whether the end is free) places one flange on the end; elsewhere it still places a pair. Valves have `e` (`flg`, `thd`, `weld`, or unset for automatic: flanged above NPS 1-1/2, per the project small-bore setting below; wafer valves are always between flanges); `endType()` / `valveEnd()` turn that into the BOM text. The valve tool bar chooses the ends. A flanged valve placed mid-pipe gets a `m:1` flange against each face through `addValveFlanges()` (skipped on a side where the pipe ends too soon); tapped near a free pipe end it sits flush on the end with one flange on the pipe side. The inspector changes ends, adds flanges, and moving, retyping, re-ending or deleting a valve moves, refits or removes its flanges (`valveFaceFlanges`, `dropValveFlanges`). In the cut list the flange to valve joint is bolted, so the valve is its own spool.
- Joints in `rebuild()` step 3: three pipes meeting with no straight run (a corner plus a third pipe) become an elbow on the two largest pipes (`j.elL`) with the third pipe branching off it by an olet (half size or less) or a stub-in (`j.corner`), with a stress warning; four pipes that form two straight runs make a real cross (two crossing cylinders); any other meeting (odd branch angle, four or more pipes that are not a cross, overlapping pipes) sets `j.bad` and shows a red ball and a warning instead of the old white sphere. The old step-5 clash code was replaced by `clashes()`, which also turns the pipes red.
- Iso conventions (compared with published iso guides): weld numbers are `W#` in a hexagon beside a dot (double hexagon for a field weld), spool numbers `S01` in a box on the spool's longest piece, item balloons stay circles, flow arrows only on the longest pipes of each line and at least 170 px apart (one per line at minimum), the Y axis is labelled Y (N).
- Deleting a fitting: fittings are derived from the joints, so `removeFitting(key)` removes the shortest pipe meeting at that joint (with the valves, flanges, items, supports and instruments on it and any cap left floating), or the cap record for an end closure. Reached from the Delete tool and from the inspector's Remove fitting button; undo restores it.
- Elevation panel: tapping the EL readout (`#elv`, above the ▲▼ buttons) opens `#lvl` with a typed height in mm, chips from `levelList()` (floor, `model.levels` named levels saved with the project, heights already found in pipe ends and nozzles), an eyedropper that takes the height of the next pipe, nozzle or equipment tapped (`pickLevel`, handled at the top of `onTap`), and Save level. `setLevel(m)` while a run is going adds a vertical pipe from the cursor to that height (refused under 50 mm), otherwise it sets the working height `elev`. In the 3D view a pale blue drop line (`setDrop`) runs from the cursor, or the point under the Pencil, down to the floor while the pipe tool is active; its EL label is one sprite whose canvas is redrawn only when the cursor's height changes, never on pointer moves. A full-size grid at the working height was tried and removed because it slowed rendering on the iPad; do not add large transparent planes or per-move texture uploads.
- Iso pictures (not P&ID symbols): `ISOA` holds a side-view picture for every valve type, flange pair and single flange, inline item, support, instrument (`i-gauge`, `i-xmtr`, `i-ctrl`), safety valve and fitting (reducer, cap, plug, olet), written in the local frame of `isoSym` (x along the pipe, up is negative y, 20 units is a valve's face to face, body fill `#dde3e6`). `isoSym` uses the picture when there is one and falls back to the flat P&ID symbol in `SYM`. Equipment is drawn as solid projected shapes (`eqPicture`: boxes and cylinders with hull outlines, painted far to near by `depth3`; pump = base, volute, guard, finned motor; vessel = cylinder, dished head, legs; every nozzle gets a stub and flange face). The P&ID sheet still uses `SYM`; the symbols sheet shows both side by side. Add a picture to `ISOA` when adding a part type, and keep it recognisable at 40 px.
- Iso symbol style: the iso header's Symbols / Pictures button sets `isoOpts.style` (`isoCtx.style`, default `sym`; `isoSvg(ln, view, tidy, style)`). In `sym` style valves, flanges and flange bars use `ISOS`, the bow-tie conventions found on most iso drawings (gate: plain bow-tie with stem and handwheel bar; globe: filled centre dot; check: filled arrow; ball: open circle and lever; butterfly: two bars with a disc; plug: filled trapezoid; control: diaphragm dome; angle, needle, diaphragm, knife, three-way and foot valves each with their own mark), and flanged valves get their flange bars from the flanges fitted against them. Parts with no `ISOS` entry (strainers, expansion joints, supports, instruments, PSV) use the `ISOA` pictures in both styles, and equipment stays the solid shapes. The symbols sheet shows the P&ID symbol and the iso symbol side by side.
- Iso symbol conventions: the `sym` style (`ISOS`) is drawn by hand in the usual iso way, and was checked against how AutoCAD Plant 3D 2023 names and combines its iso symbols (its skey map: a valve body plus an operator such as a hand stem, lever or diaphragm dome; control valve = gate bow-tie with a diaphragm operator). No Autodesk geometry, symbol file or catalog data is copied into this repo, because the repo and its Pages site are public. A session that exported Plant 3D blocks to check conventions must keep that data outside the repo.
- Standards: `spec.std` is `asme` (class 150), `jis` (10K) or `en` (PN16), picked in the project spec. `STD` holds, per set, the rating word (`cls`, which replaces the text `150#` in every BOM description inside `add()`), the size table (JIS pipe outside diameters differ from ASME, EN uses ISO 4200), the flange table, bolts, and the standard and material text for pipe, fittings, flanges, gaskets, bolts and valves (`stdOf` puts it in the third column of `bomRows()`, in the BOM panel, the CSV and the iso material list). `applyStd()` swaps the live `SIZES`, `OD`, `FL` and `BOLTS` at the start of every `rebuild()`. `spec.sizeMode` is `NPS`, `DN` or `A` (JIS A, same numbers as DN with an A); `sz(n)` and `szs(n)` write it, never write `'NPS ' + n` directly. Choosing a standard also sets the usual size designation. Valve face to face, tee, cap and reducer lengths stay on the ASME tables for every set. All figures are typical values written from memory, see the BOM note, and the project piping class overrides them.
- Small bore (NPS 1-1/2 and below) takes `spec.small`: SW 3000# (default), THD 3000# or BW. `endConn(n)`, `pipeEnd(n)` and `valveEnd(kind, n)` turn that into the BOM wording.
- Model: `{ pipes: [{a, b, n, s}], valves: [{p, d, n, s}] }`, saved in `localStorage` under `pipedraft.model.v1`. Keep old saves loadable (`s` defaults to 40).
- Fittings are not stored. `rebuild()` derives them from joints: elbow (long radius 1.5D, real torus bend), reducer, equal or reducing tee, weldolet when the branch is at most half the header, cross. Pipes are trimmed back to each fitting. Valves are inline and their face-to-face length comes off the pipe in the BOM.
- Catalogue dimensions are written from ASME B16.9 and B16.10 from memory. Treat them as unverified until checked against the standard.
- Do not copy Autodesk spec or catalog data into this repo. It is public.

## Features
- Tools: Navigate, Select (inspector edits size, schedule, line number, valve type, equipment rotation), Pipe, Valve (gate, globe, check, ball), Flange pair, Cap, Equipment (pump, vessel and custom equipment, with nozzles as pipe start points), Measure, Delete.
- Pipe tool: snap 50, 100 or 250 mm; optional 45° turns; start a run on a pipe end, a nozzle, or the middle of a pipe (the pipe is split and a tee appears); a new end landing on a pipe splits it too.
- Views: Iso, Top, Front, Right, Fit, orthographic toggle, dimension labels. Iso sheet is generated as SVG with centreline lengths and a line-number summary.
- The isometric sheet follows isometric practice and must not borrow P&ID drawing habits. `isoSvg()` draws pipe as single lines, each symbol skewed into the plane of its pipe (`isoSym` wraps the flat `SYM` drawing in an SVG matrix built from the projected pipe direction and the up direction), item balloons that point at a material list on the sheet, dimension lines with arrowheads along each pipe, EL at free ends, equipment as dashed wire outlines with nozzles, instruments as a stem and a small circle with the tag beside it, and an axes mark. No P&ID bubbles. Components find their BOM row through `compDesc` (filled by `add()` while `curRef` points at the component being built), so a new component type needs its `curRef` line in `rebuild()` and a `balloon()` call in `isoSvg()`. Pipe stock and weight are notes under the list, not items. The P&ID sheet and the symbol reference sheet keep the flat symbols.
- Symbols: `SYM` holds every isometric symbol (valve kinds, flange pairs, inline fittings, reducer, cap, plug, olet, weld dot, pump, vessel) with a name and a tag prefix. `isoSvg()` draws only the symbols in use, numbers each placed item (GV-1, FL-2, P-1), and lists them in a legend. `legendSvg()` is the full reference sheet in the ⋯ menu. A new part type needs a `SYM` entry.
- Instruments: `model.instr` holds `{k, p, d, n, num, link?, eq?}`. `INSTR` lists the types (PI, TI, FI, PT, TT, FT, LT, PIC, TIC, FIC, LIC, PSV). They sit on a pipe (`d`, `n`) or on equipment (`eq` index). A controller gets the loop number of a transmitter of the same variable that has no controller yet (`nextNum`), and `link` is the index of a control valve it drives. A pipe-mounted instrument whose point is no longer on a pipe is reported in Check.
- Tags: `assignTags()` gives valves, flanges, inline fittings and equipment one tag list, used by both the isometric and the P&ID sheet. Instrument tags come from `instrTag()`.
- P&ID sheet: `pidSvg()` builds a schematic from the joints. Nodes are equipment, branches and free ends. Runs are the pipe between two nodes, and each run is a horizontal line with its valves, flanges, inline fittings, reducers and instruments in order. The straight-through leg continues on the row and a branch drops to a new row. Not to scale, flow direction not shown, signal lines are dashed.
- Flow: each pipe has `fl` (1 = from A to B, -1 = from B to A, 0 = not set). New pipes take the "Flow on new pipe" setting, splitting a pipe keeps it, `setRunFlow` carries one direction through elbows and reducers, and Select edits one pipe. Arrows show in 3D (toggle in ⋯), on the isometric sheet and on the P&ID. Check `valves` have `rev` to flip them, and a check valve against the flow is reported. Two pipes whose flow meets head-on at a joint are reported.
- Supports: `model.supports` holds `{p, d, n, t}` with `t` one of shoe, guide, anchor, hanger, spring. Horizontal pipe takes all five, vertical pipe takes a guide or an anchor (a clamp ring with a bracket). `SPAN` gives the rough maximum unsupported span per size, from memory of an MSS SP-69 style table, and long gaps are reported (pipe ends count as supported). Supports are tagged (SH, GD, AN, HG, SPH) and drawn on the isometric sheet, not on the P&ID.
- Hydraulics: `model.fluid` (key into `FLUIDS`) and `model.lines` (`{ 'L-001': { q: m³/h } }`) feed `hydraulics()`. It works per line number: velocity, Reynolds number and Darcy-Weisbach friction (Churchill friction factor, 0.045 mm roughness) on each trimmed pipe length (`pipeLen`, with valve and inline item lengths taken off), fittings by Crane TP-410 style K (`FT`, `ELBOW_K`, `VALVE_K`, `ITEM_K`, control valve from `CV`), reducers as contraction or expansion by flow direction (small-bore velocity), and an elevation term when every pipe of the line has a flow direction. Velocity above 3 m/s is reported in Check. Equipment nozzle losses and flow splits at tees are not included. The tests compare against the Python `fluids` package, so keep those reference numbers if the formulas change.
- Drawing axes follow CAD: X and Y horizontal, Z up (the scene itself has Y up, so CAD Y is scene Z). Pipes are drawn by aiming: `aim()` picks the axis whose screen direction best matches the pointer (or the locked axis from the Auto, X, Y, Z buttons) and measures the length where the pointer ray passes closest to that axis line. Status shows X, Y, Z in mm; the guide line takes the axis colour (X red, Y green, Z blue). The ▲ ▼ buttons still add fixed 0.5 m vertical steps, and move the start plane when no run is active.
- Checks: clash detection between pipes that share no joint, size changes at elbows or tee headers, pipes shorter than their fittings.
- File: save and open project JSON, BOM CSV, DXF centrelines (mm, Z up), PNG image. On iPad these go through the share sheet.
- Fitting catalogue, all derived from joints by `rebuild()`: elbow (LR 1.5D, SR 1.0D, 3D, any angle), reducer (concentric, eccentric, swage nipple; length from `RED_H` by large size), tee, reducing tee, lateral 45°, weldolet, sockolet, threadolet, sweepolet, half coupling, nippolet, stub-in (with or without reinforcing pad), cross, cap, plug. Pipes are cut back to each fitting.
- `model.spec` holds project defaults (`elbow`, `reducer`, `olet`, `branch`). `model.fit` maps a joint key (`"x,y,z"` in mm) to overrides (`el`, `red`, `br`, `olet`). Select a fitting to edit its override; the Spec button edits the defaults.
- Placed items: valves (gate, globe, check, ball, butterfly, plug, control, angle, needle, diaphragm, knife gate, three-way, foot), flange pairs (weld-neck, slip-on, lap-joint with stub ends, threaded, socket-weld, orifice pair with plate), blind flange on a pipe end (`flanges` with `t: 'bl'`), inline fittings in `items` (coupling, union, Y-strainer, basket strainer, expansion joint, spectacle blind, orifice plate, sight glass, flow meter, steam trap, rupture disc, flame arrestor, flexible hose), end closures in `caps` (`[x, y, z, 'cap' | 'plug']`). New valve kinds, inline items and flange types need entries in the face-to-face or length table, `VALVE_K` or `ITEM_K`, `PARTS`, and `SYM`.
- Custom parts (⋯ → Project → Custom parts, Parts → Custom): `model.custom` is a project library `[{id, name, brand, model, kind:'inline', len (mm, 20 to 3000), wt (kg, optional), k (loss coefficient, 0 = ignored), prefix (tag, default CU), img?}]`, saved with the project, in File → Save project and in backups, and moved between projects with File → Export custom parts (.json) / Import custom parts (merge by id; a clashing id gets a new one). `normalize()` defaults it to `[]` and drops unusable entries. A placed part is an ordinary `model.items` entry with `t = 'cu:' + id`, so geometry (cylinder of the pipe size and the given length, `rebuild()` item branch), BOM, tags, cut list, welds, iso balloon, move/copy/mirror, `subsetFor` and delete need no special case; `isCu(t)` and `CUX` (type to live data, built by `syncCustom()` at the start of every `rebuild()`) are the only switches. `itemLen`, `itemK` and `cuDesc` read `CUX`. BOM text is `name, brand model, NPS x`; brand, model and weight go in the standard column (`add()`'s 5th argument `note`, returned first by `stdOf`). `syncCustom()` also registers `SYM`, `ISOS` and `ISOA` entries for each `cu:` type (a generic box with a cross; with a picture the `pic` style draws it as an `<image>`) and refreshes the Custom chips only when names change. Each placed item caches `cn, cb, cm, cl, ck, cp` (name, brand, model, length mm, K, prefix) so that when its library entry is deleted it keeps its name, length and tag; the panel warns with the placed count (two-tap delete), the inspector shows it as deleted, and it cannot be placed again. Editing an entry updates every placed copy because nothing but the type is stored on the item. Pictures: picked with `<input type=file accept=image/*>`, scaled in a canvas to at most 160 px on the long side (`cuImgSize`), JPEG quality 0.8 falling to 0.35 until the data URL is at most 40000 characters (`cuImgEncode`), otherwise refused; `cuImgOk` also gates files and imports (only `data:image/jpeg|png|webp;base64`). The joint of a custom part is treated as a butt weld in the cut list (no flange, gasket or bolt rows are added), and weight is only shown in the BOM column, not added to the pipe weight. Safety limits: at most 300 entries (`CU_MAX`), `cuTxt` cleans every text (40 characters, no leading = + @), an item's cache is clamped in `syncCustom()`, items with an odd `cu:` type are dropped by `normalize()`, a part longer than the pipe left raises a warning, backups stop at about 1.2 million characters in total (`BK_CHARS`) and undo history at 30 MB, because pictures live inside the project JSON. Equipment entries are described in the next item.
- Custom equipment (kind `'equipment'` in `model.custom`; ⋯ → Project → Custom parts → Add equipment, Parts → Equipment chips): `{id, kind, name, brand, model, prefix (default EQ), wt, col (0 to 5, `EQ_COL`), shape 'box'|'cyl', w, d, h | dia, h (mm, 100 to 20000), noz: up to 8 of {x, y, z, dir, n}}` (img is kept but not drawn). Nozzle x, y, z are mm from the middle of the base in the equipment's own frame, CAD axes (z up, so scene `[x, z, y] / 1000`); `dir` is one of `+X -X +Y -Y +Z -Z` pointing out of the body; a nozzle may sit up to 500 mm outside the outline (`eqValidate` clamps; the panel refuses bad numbers). A placed copy is `model.equip` `{k: 'cu:' + id, p, r}` and rotates by `r` quarter-turns about the vertical exactly like the pump and vessel. `syncCustom()` builds `CEQ` (type to an `EQUIP`-style def with `noz` in scene metres, `build`, `W D H`, `shape`, `custom: true`), so `eqDef(k)` replaces `EQUIP[k]` everywhere: `equipNozzles`, `rebuild()` (mesh, nozzle stubs, `nozList` with `e` = equipment index, BOM row `name, brand model` with brand, model and weight in the standard column), `eqInside()` for the clash outline (shrunk 30 mm, nozzles exempt within 0.3 m), `eqGeom` / `eqPicture` on the iso (one `boxPrim` or `cylPrim`, nozzle stubs and N numbers as before), the P&ID (a `SYM` rectangle or vessel shape with the prefix tag, `eqIsVessel`), tags (`SYM[k].tag`), the inspector and the Parts hint. Each placed copy caches the cleaned entry in `q.cu` (refreshed from the library in `syncCustom()`, re-cleaned when the entry is gone, so at most 8 nozzles and 40 character texts), which keeps a copy alive when its entry is deleted; a deleted entry cannot be placed again. `normalize()` drops equipment whose type is not built in and not `cu:` + a safe id with a library entry or a valid cache, or whose position is not three finite numbers, forces `r` to 0 to 3 and renumbers `instr[].eq`. Editing an entry updates every copy; if a nozzle edit leaves pipe ends that were on a nozzle, the pipes stay and a toast counts them (`nozPipes`).
- Fittings are derived from joints, but the Parts list also has tools that make the geometry for you, so every common fitting can be placed by name. Branches (tool `branch`, chip `bk`): tap a pipe, the pipe is split there (`splitAt`), a 0.3 m stub starts in the chosen direction (Up, Near, Far, Down, from `perpDir`) and a per-joint override in `model.fit` forces the fitting (tee, reducing tee, olets, stub-in, with or without pad); Lateral 45° leans the stub, Cross adds an opposite stub. The stub end becomes the run end, so switching to Pipe carries on from it. Reducers (tool `reduce`, chip `rk`): tap a pipe, `resizeRun` gives the half toward the nearer end and the run beyond it (through elbows, up to the next node) the size in the size box, and things placed on those pipes follow. Return bend (Ends, chip `ret`): a U of two elbows. Two 90° elbows with no straight pipe between them and legs pointing the same way are reported as one return bend.
- The three-way valve has a side port, pushed into `nozList` with `e: -1` so pipes can snap to it like a nozzle (Select, Turn the side port rotates it). Anything that reads `nozList` for equipment must ignore `e < 0`.
- Dimensions for the extra valve kinds (angle, needle, diaphragm, three-way, foot) reuse the globe, gate or check table, and inline item lengths are rough. Treat them as placeholders.
- Eccentric reducers are drawn concentric in a different colour. The centrelines stay on the pipe axis.
- Inline item lengths and the lateral dimensions are rough figures, not from a standard.
- Model arrays: `pipes`, `valves`, `flanges`, `caps` (pipe end points), `equip` (`{k, p, r}`), `custom` (library of user parts). `normalize()` fills defaults so old saves load.
- `window.PipeDraft` exists only for the headless tests.

## Screen layout (keep it uncluttered)
- Header: view buttons (Iso, Top, Front, Right), Fit, Undo, BOM, and the ⋯ menu (isometric sheet, project spec, orthographic, pipe lengths, file actions).
- Left rail: six tools only: View, Select, Pipe, Parts, Measure, Delete. Parts opens a narrow scrolling list (218 px) with one folding section per category (Valves, Flanges, Inline, Ends, Equipment, Supports, Instruments), one section open at a time. Choosing a row arms that part, then tap the canvas. The list is built once by `buildParts()` and `syncParts()` only changes classes, so the scroll position survives every tap.
- The ⋯ menu has three folding groups (Sheets, Project, File), one open at a time. Put new menu actions into a group, do not add loose buttons.
- Bottom centre: context bar shown only for Pipe and Equipment (Rotate). For Pipe it is the settings summary alone until a run starts, then the axis buttons (Auto, X, Y, Z↑) and Finish run appear. The summary button opens the pipe settings sheet (size, schedule, line number, snap, flow on new pipes, 45° turns).
- Right column: inspector, project spec and BOM, shown only when opened. Elevation up and down sit bottom right.
- Do not add toolbar buttons. New parts go into `PARTS` as chips, new actions into the ⋯ menu, new per-item settings into the inspector.
- Touch targets are at least 48 px. Tapping the canvas closes the pipe settings and the ⋯ menu.

A valve's angle is `hw` in degrees about its pipe from the usual up position, equipment turns about the vertical through its base. Equipment `r` is now in quarter turns and may be fractional (`normalize()` keeps a quarter of a degree, 0 to 4), so a typed angle works too: the inspector has an Angle in degrees box for both (`i-hwn`, `i-rota`, `rotApply` keeps a quarter of a degree). - Rotate mode (quick bar Rotate, `rotMode`): while on, a drag from anywhere on the screen turns the selected valve or equipment by how far the pointer goes round it, measured on the ring plane (`rel` drag in `rotMove`; refused with a toast when the plane is seen nearly edge on, `rotFacing`), and the bar shows the angle (`q-ang`).
